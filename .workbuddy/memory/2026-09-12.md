## seed.ts 的 slug 改为随机 id（最终定为 36 位 UUID）

- 4 条种子数据 slug 由可读名（hotpot-feast 等）换成 **36 位 UUID**，如 `83436b1f-3208-4082-9e2e-6aa29e13af3c`（先做过一版 16 位 `8-4-4`，用户要求改成 36 位）。
- 值**写死**在数组里（不是运行时随机），保证 `upsert({ where: { slug } })` 仍然幂等；运行时随机会导致每次 seed 都插 4 条新记录。
- 新增导出工具 `newId()`（`node:crypto` 的 `randomUUID()` 直接返回 36 位），供后续手工生成新 id，避免 eslint unused 警告。
- 影响：详情页 URL 变为 `/{id}`（路由 `/[slug]` 不变）；admin 新建/复制的 SLUG_RE 校验（小写字母数字连字符）天然放行 hex id。
- 注意：库里已有的旧 slug 行不会被迁移，重跑 seed 会新增 4 条 id 记录，旧记录仍在。

## /admin 口令「不正确」排查（输入值归一化 + 错误提示分层）

- 现象：用户填 `.env` 里一模一样的值，仍提示「口令不正确」。服务端逻辑本身没问题（curl 模拟表单 POST 能拿到 `Set-Cookie`）。
- 根因是两个「提示不分层」+「输入未归一化」：
  1. `ADMIN_SESSION_TOKEN` 未在服务端读到时，`isValidToken` 也返回 false，提示同样是「口令不正确」，完全误导；
  2. 只做了 `trim()`，没去掉**成对引号**，也没处理直接粘贴整行 `ADMIN_SESSION_TOKEN="xxx"` 的情况 —— 从 `.env` 复制时极易带上，必然比对失败。
- 修复：`src/lib/admin/auth.ts` 新增 `normalizeTokenInput()`（trim → 去 `KEY=` 前缀 → 去成对引号），`isValidToken` 走它；`loginAction` 改为先判 `isAdminConfigured()` 返回「服务端未读到 ADMIN_SESSION_TOKEN：请确认 .env 并重启 dev server」，再判「口令不正确」。
- 验证：裸值 / 带双引号 / 粘贴整行 三种都能下发 cookie，错误口令不下发且提示「口令不正确」。
- 环境坑：本机有 `HTTP_PROXY=127.0.0.1:58207`，headless Chrome 走代理会 ERR_CONNECTION_REFUSED（curl 需 `--noproxy '*'`）；`ps` 被沙箱禁止，用 `pgrep -laf` 替代。
- 期间 3000 端口的 dev server 曾消失（用户可能跑了 `next build`），已重新拉起。
