## 11:40 上传图片 docker 数据卷持久化（public/uploads）
- 背景：后台封面图落在 public/uploads/deals（src/lib/admin/uploads.ts），但 compose 原先挂的是 ./data/uploads:/app/public/uploads/deals，与实际落盘目录不一致。
- 改法：
  - docker-compose.yml：改为 `${UPLOAD_HOST_DIR:-./public/uploads}:/app/public/uploads`（挂父目录，相对路径随 compose 文件位置解析 —— 本地=项目根 public/uploads，服务器=~/app/xiaozhu/public/uploads；可用 .env 的 UPLOAD_HOST_DIR 覆盖）。

  - .github/workflows/deploy.yml：部署脚本新增第 3 步，mkdir -p ~/app/xiaozhu/public/uploads/deals 并 chown 1001:1001（有 sudo 用 sudo -n，否则直接 chown，失败只告警不中断），原 3~6 步顺延为 4~7。
- 权限要点：容器以 uid 1001 (nextjs) 运行，Linux 宿主目录必须 chown 1001:1001，否则上传 EACCES；目录不存在时 docker 会建但属主是 root。macOS Docker Desktop 不强制 uid，已用 redis 镜像 --user 1001 冒烟验证可写（WRITE_OK）。
- 验证：docker compose config 解析出 source=/Users/yangpan/Desktop/xiaozhu/public/uploads → target=/app/public/uploads。

## 12:23 修复 deploy.yml ssh heredoc 漏引号导致部署变量在 runner 端提前展开
- 报错：CI 进入 deploy 步骤后 `seq: invalid floating point argument: ''`（PULL_RETRIES 在 runner 上未定义被展开为空）+ `mkdir: cannot create directory '/deals'`（HOME 被展开成 runner 的 HOME 而非远端 /home/ubuntu）。
- 根因：deploy.yml 第 347 行 `ssh ... bash -se <<EOF`（**未带引号**），GitHub Actions runner 在把脚本经 ssh 传给远端前就展开了所有 `$变量`；而 329 行写 .env 的 heredoc 用的是 `<<'EOF'`（带引号，正确）。注释里也明确要求用带引号 EOF 禁止本地展开，但 347 行漏了。
- 修复两处：
  - 347 行 `<<EOF` → `<<'EOF'`，使 $HOME/$PULL_RETRIES 等改由远端 ubuntu bash 正确展开。
  - 374 行 `${IMAGE}:${TAG_SHA}`（原靠 runner 的 step env 展开，改 <<'EOF' 后远端拿不到）改为 Actions 表达式 `${{ needs.build-and-push.outputs.image }}:${{ needs.build-and-push.outputs.tag_sha }}`（与 329 行 `${{ secrets.* }}` 同理，不受引号影响）。
- volumes 设置本身正确：`${UPLOAD_HOST_DIR:-./public/uploads}:/app/public/uploads` 相对 compose 文件位置解析为 ~/app/xiaozhu/public/uploads；之前 ls 看不到 public/ 是因为 mkdir 步骤失败未创建，修复后由远端脚本创建并 chown 1001。
- 顺带确认：本次 CI 已跑到 deploy 步骤，证明上一轮 admin/layout.tsx 的 force-dynamic 修复使 build 通过。
- 约定：GitHub Actions 里凡是 `ssh ... bash <<EOF` 把脚本传远端执行的，heredoc 必须带引号 `<<'EOF'`；需要 runner 端注入的值一律用 `${{ }}` 表达式，不能在脚本里写 `${STEP_ENV}`。
